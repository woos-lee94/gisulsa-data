# 기술사 6개월: 아이폰 앱 이식 지시서

## 목표

`web/` 폴더의 웹앱(예전 Netlify PWA)을 화면·기능·데이터 그대로 아이폰 앱으로 만든다. Netlify 웹앱은 2026-10에 내렸고, 이제 `web/`은 아이폰 앱의 화면 원본이다.
학습 기록은 각자 휴대폰에만 둔다. 공유, 랭킹처럼 다른 사용자와 이어지는 기능은 넣지 않는다.
예외 하나: 관리자가 승인한 휴대폰만 앱을 여는 회원 승인(비밀번호 없는 아이디, 휴대폰마다 하나 고정). 서버 코드 없이 Firebase(익명 Authentication + Firestore)를 REST로 부른다(`docs/firebase-setup.md`).

## 이 저장소에서 지킬 것

- 이 폴더(`app/`)는 아이폰 앱 코드다. Expo 프로젝트 루트도 `app/`으로 둔다(`app/package.json`).
- 저장소의 `data/`와 `pipeline/`은 예약 작업(매일 세트, 토요일 모의고사) 영역이다. 앱 작업에서는 읽기만 하고 고치지 않는다.
- 예약 작업이 거의 매일 main에 올린다. main에 올릴 때는 `git fetch origin main && git rebase origin/main && git push origin HEAD:main`.
- 이 저장소는 공개다. 키·비밀번호·인증서·`.env`를 올리지 않는다(`app/.gitignore`).

## 화면(web/)의 구조

- 순수 HTML·CSS·JS, 빌드 도구 없음. `index.html`이 `data_cards.js → data_cards_k.js → data_essays.js → data_kichul.js → data_plan.js → app.js` 순서로 읽는다.
- `app.js`: 해시 라우터(아래 탭 `#today`·`#week`·`#review`·`#practice`·`#more`와 화면 `#set/YYYY-MM-DD`, `#mock/YYYY-MM-DD`, `#kichul/r/140`, `#schedule` 등. 예전 `#study`·`#test`는 연습 탭), `render()`, `data-act` 속성으로 이벤트 위임. 주소는 바꿔 쓰기만 한다(아래 "내비게이션").
- 내장 데이터
  - `data_cards.js` 기본 카드, `data_cards_k.js` 기출 보강 카드 98장, `data_essays.js` 논술 모범 목차
  - `data_kichul.js` 기출 제116~140회 775문항 요지와 카드 연결표
  - `data_plan.js` 단계·주차 틀 30개·정기시험 규칙(`PE_SCHED`)·요일별 루틴·Claude 프롬프트
- 학습 기록 저장: `localStorage` 두 키
  - `pe_state_v1`: 학습 기록 `S` (settings, cards 간격반복 상태, wrong 오답 노트, sp 세트 진행(rev 세트 복습 단계마다 마지막으로 한 날, rvd 그 단계를 처음 끝낸 날), tk 손으로 친 일·표시, today 그날 고정한 오늘 몫, wk 주마다 기록, days 날마다 정한 공부 시간(쉬는 날·짧은 날, v3.1), checks 예전 할 일 체크(읽기만) 등. settings에는 v3.1부터 nextTarget·schUndo·schSent·schSig·slipNo(아래 "시험 일정 살펴보기"))
  - `pe_sets_v1`: 받아 온 세트·모의고사·새 기출·저장소 일정(plan)
- 자료 받아 오기: 앱을 열 때 `https://raw.githubusercontent.com/woos-lee94/gisulsa-data/main/data/index.json`을 읽고, 새로 올라온 `sets/YYYY-MM-DD.json`, `mocks/YYYY-MM-DD.json`, `kichul.json`을 받는다.
  이 저장소에는 Claude Code 예약 작업이 평일 06:21에 세트를, 토요일 06:21에 모의고사를 올린다. 파일 형식은 `../pipeline/spec_set.md`, `../pipeline/spec_mock.md`, 실제 파일은 `../data/`.
- 시험 일정: `data_plan.js`의 `PE_SCHED`와 `app.js`의 `computePlan()`이 준비 시작일에서 6개월 이상 남은 정기시험을 목표로 잡고 주차를 배분한다. 저장소 `data/index.json`의 `plan`과 비교해 다르면 시험 일정 화면에 경고와 "변경 요청 복사"를 띄운다. 목표만 바꿀 때 이번 주가 달라지면 다음 월요일부터 바꾼다(v3.1, 아래 "시험 일정 살펴보기").
- 웹앱 시절 브라우저 기능을 쓰던 곳(지금은 `bridge.js`가 앱 기능으로 잇는다)
  - `navigator.clipboard` 복사: 첨삭·채점 요청, 프롬프트, 백업, 일정 변경 요청(`copy()` 함수)
  - Blob 다운로드: 백업 파일 저장(`backup-dl`)
  - `confirm()`: 복원·초기화 확인
  - `AudioContext`: 타이머 알림음(`beep()`), `navigator.wakeLock`: 타이머 동안 화면 켜 두기
  - 서비스 워커·PWA 매니페스트·아이콘·`netlify.toml`, Pretendard CDN 링크: 웹앱을 내리면서 지웠다

## 바꾸지 않는 것

1. 자료 저장소 주소와 JSON 형식. 예약 작업이 이 형식으로 계속 올리므로 앱이 거기에 맞춘다. 저장소(woos-lee94/gisulsa-data)는 공개로 두고, 앱은 인증 없이 raw 주소로 읽는다.
2. 백업 JSON 형식 `{"state": S, "sets": SETS}`. 웹앱의 더보기 → 백업에서 복사한 기록을 앱의 복원에 붙여 넣으면 진도·오답·받은 세트가 그대로 이어져야 한다.
3. 간격·다시 보기·시험 날짜·주차·D-day 계산(화면 구성과 문구는 v3.0.0에서 정리): 간격반복 간격 [0,1,3,7,14,30,60]일, 세트 복습 1·3·7·14·30일, 정기시험 날짜 규칙, 주차 지도, D-day. 새 기록은 `S`에 더하기만 하고(`tk`·`today`·`wk`·`mockp[D].g/.sc`·`settings.budget`·`sp[D].rvd`, v3.1 `days`·`wk[주].cu·ph·gn·gd·off·left`·`settings.nextTarget·schUndo·schSent·schSig·slipNo`), 예전 백업도 그대로 복원된다. 시험 일정을 미뤄도 `computePlan`·`buildMap`·정기시험 규칙은 그대로이고 바뀌는 날만 정한다.
4. 서버를 두지 않는다. 원격 푸시도 서버가 필요하므로 쓰지 않는다. 회원 승인만 Firebase(관리형, 서버 코드 없음)를 쓰고 학습 기록은 보내지 않는다.

## 만드는 방식: Expo(EAS) + WebView

화면과 로직은 `web/app.js`를 그대로 쓴다. React Native로 다시 짜지 않는다(기능이 많아 다시 짜면 동작이 어긋난다).

- Expo 앱 하나에 `react-native-webview`로 `web/` 파일을 앱 안에 묶어 띄운다. 인터넷 없이도 열려야 한다.
- 웹 코드 수정은 "네이티브 다리" 한 곳으로 모은다. `window.PE_NATIVE`가 있으면 그것을, 없으면 브라우저 기능을 쓴다(브라우저로 바로 열 때와 `tests/app.test.js`).
  - 저장: `pe_state_v1`·`pe_sets_v1`을 네이티브 저장소(expo-file-system 또는 AsyncStorage)에 쓰고, 앱 시작 때 WebView에 주입한다. WebView의 localStorage만 믿지 않는다.
  - 복사: expo-clipboard
  - 백업 파일: expo-file-system에 쓰고 expo-sharing 공유 시트로 내보내기
  - 타이머 화면 켜 두기: expo-keep-awake
  - `confirm()`: WebView에서 뜨는지 실기기로 확인하고, 안 뜨면 네이티브 Alert로 잇는다
  - 웹폰트: Pretendard 가변 폰트를 앱에 넣어 CDN 없이 쓴다
  - 서비스 워커: 쓰지 않는다(지웠다)
  - 받아 오기: raw.githubusercontent.com은 CORS를 모두 허용한다. 로컬 파일 출처에서 막히면 네이티브 fetch로 받아 넘긴다
- 화면: WebView를 화면 전체로 쓴다. CSS에 `viewport-fit=cover`와 `env(safe-area-inset-*)`가 이미 있다. 다크 모드(`prefers-color-scheme`)가 기기 설정을 따라가는지 확인한다.
- 앱 이름 "기술사 6개월", 아이콘 `assets/icon-1024.png`(불투명 1024×1024).

### 네이티브라서 더하는 것(서버 없이, 설정에서 켜고 끄기)

- 로컬 알림(expo-notifications 로컬 예약): 평일 아침 "오늘 세트 확인", 일요일 "복습 비우기". 시간은 설정에서 고른다.

## 배포

- 사용자 혼자 쓰므로 `eas build -p ios` → TestFlight 내부 테스트로 설치한다.
- TestFlight 빌드는 90일 뒤 만료되므로 그 전에 다시 빌드한다.
- App Store 공개 출시는 이번 범위가 아니다.
- 사용자는 Windows PowerShell에서 아래 순서를 그대로 쳐서 빌드한다(PowerShell을 연 위치, 보통 `C:\Users\이름`에서). 빌드 안내는 이 순서를 기준으로 하고, 다른 폴더 경로를 가정하지 않는다.

  ```powershell
  git clone https://github.com/woos-lee94/gisulsa-data.git
  cd gisulsa-data
  git stash
  git checkout main
  git pull
  git stash pop
  cd app
  npm ci
  npm test
  eas build -p ios --profile production --auto-submit
  ```

  - 회원 승인을 쓰므로 처음 한 번은 빌드 전에 EAS 환경 변수 두 개를 넣는다(`docs/firebase-setup.md` 2). 없이 빌드하면 앱이 "설정이 빠진 빌드" 화면에서 멈춘다.
  - 이미 받은 폴더가 있으면 `git clone`은 "already exists" 오류를 내고, 나머지 줄이 그 폴더를 최신으로 맞춘다.
  - `git stash`·`git stash pop`은 `eas init`·`eas build`가 PC의 `app.json`에 적은 EAS 프로젝트 번호(`owner`, `extra.eas`)를 지키려고 쓴다. 저장소의 `app.json`을 고칠 때 그 줄과 겹치지 않게 한다.
  - 앱 변경은 사용자가 `main`으로 받으므로 `main`에 올린다.

## 받아들이는 기준

1. 회귀 검사(`app/`에서): `npm test`(`tests/app.test.js`·`plan.test.js`·`native.test.js`·`gloss.test.js`) → 파일마다 마지막 줄 "모두 통과", FAIL 줄 없음.
2. 실기기 확인
   - 첫 실행 → 자료 받아 오기 → 오늘 세트 열기, 퀴즈, 논술 목차, 카드 넘기기
   - 앱을 완전히 닫았다 다시 열어도 진도·오답이 남아 있음
   - 비행기 모드에서도 열리고 내장 카드·기출이 보임
   - 웹앱에서 복사한 백업을 붙여 넣어 복원 → 진도가 그대로 이어짐
   - 더보기 → 시험 일정에서 시작일 바꾸기 → 미리보기 → 저장 → 변경 요청 복사
   - 복사 버튼, 백업 파일 내보내기, 타이머 알림음과 화면 켜 두기
   - v3.1.0: 오늘 시간 → 오늘은 쉬어요(미리 보기) → 쉬는 날 카드 → 다시 공부할래요, 이번 주 날마다에서 앞날을 쉬는 날로, 설정의 쉬는 날·짧은 날 기간, 시험 일정 → 다음 회차와 비교 → 회차 줄 → 미리 보기 → 저장(변경 요청이 같은 탭에서 복사됨) → 바꾸지 않기
   - v3.0.0: 왼쪽 가장자리 밀기(위로, 탭 첫 화면에서는 그대로, 창이 열려 있으면 닫기), 가리며 외우기 테이프 긋기와 아래 붙은 조절 줄, 입력 칸 자판과 아래 막대, 글자 크기 "아주 크게"·다크 모드의 오늘·이번 주·숙제·모의고사(파란 버튼 하나, 두 줄 제목), 모의고사 시간 끝 창(앱을 내렸다 올 때 포함), 예전 기록으로 처음 열 때 "바뀐 점" 창 한 번

## 앱 폴더

- `web/`: 앱 화면 원본(v3.1.0, 네이티브 다리 포함). `index.html`의 `?v=N`(지금 9)은 `tests/app.test.js`가 스크립트를 찾는 표시라 남겨 둔다. 버전은 `app.js`의 `APP_VER`, `app.json`의 `expo.version`, `package.json`의 `version`(과 `package-lock.json`의 앱 줄 두 곳)을 함께 올린다(`tests/native.test.js`가 확인)
- `tests/`: jsdom 회귀 검사와 가짜 저장소(`tests/fake/data`)
- 확대 막기: `index.html` viewport에 `maximum-scale=1, user-scalable=no`(WKWebView는 이것을 따른다. 글자 칸을 누를 때 16px보다 작은 칸이 확대되던 것도 막는다), `styles.css`의 `html{touch-action:manipulation}`(두 번 눌러 확대)
- `assets/icon-1024.png`: iOS 앱 아이콘
- 자료 형식은 `../pipeline/spec_set.md`, `../pipeline/spec_mock.md`, 실제 자료는 `../data/`

## 화면 구성(v3.0.0): 아래 탭 다섯

- **오늘**(`#today`, `vToday`): 머리(달력 아이콘 · 날짜, 공휴일이면 아래 줄에 이름 · "n주차 · 단계" · D-day) → 날짜 일 핀(원서접수·48시간 복기) → 한 줄 안내(월요일·단계 시작) → 이어서 → 상태 줄 "오늘 몫 n개 · 약 X"(맨 위 핀의 분도 넣어 "(복기 2시간 30분 포함)")와 "오늘 시간" → **오늘 몫**(블록마다 번호 줄, 펼친 첫 줄에 화면의 하나뿐인 파란 버튼과 "나중에", 필수 줄마다 못 하면 "일요일까지"·"오늘만"·"다시 나와요"·"다음 모의 전까지". 평일에 시각이 지난 블록에 남은 줄이 있으면 그 블록을 끝낸 줄까지 통째로 지금 블록 위에, 번호는 고정한 순서 그대로) → 다른 날로 옮긴 것(손글씨 몫은 남은 세트 날짜까지)·놓아준 것·시간이 되면(접힘) → 이번 주(띠, 남은 필수 / 이번 주 공부 시간, 다 하면 · 지금, 줄 5개까지) → "오늘 몫 다시 짜기". 체크리스트는 없다(요일별 루틴은 로드맵 "요일별 루틴(참고)"). 할 몫이 없으면 카드 하나(파란 버튼 하나, 받아 오는 상태(받아 오는 중…·받아 오지 못했어요 → 다시 받아 오기)도 이 카드 하나에), 시험 날은 시험 카드와 이번 주 체크(단계 안내 없음). 준비 시작 전과 본시험 48시간 복기 뒤는 머리와 카드 하나뿐(D-day 자리는 "시험 후"). v3.1: 쉬는 날은 상태 줄 "오늘은 쉬는 날"과 쉬는 날 카드(파란 버튼 "다시 공부할래요")뿐, 이번 주 칸의 밀린 몫 줄, 시험 일정을 바꾸기를 기다리면 머리 줄 끝에 "· 2/8부터 제143회".

## 오늘 몫·이번 주(app.js "11-0. 오늘 몫·이번 주")

- 한 함수가 앱이 이미 쓰는 기록에서 할 일을 모두 만든다: `taskList(t)`(읽기만, `sp()`를 부르지 않아 세트 복습 시계를 돌리지 않음. 줄 `{id, k, need 필수·권장·여유, p 우선순위 0~7, blk 블록, min 남은 분, roll 못 하면, fill 넘침 단계로 접거나 놓아주지 않는 줄(세트 복습·카드 복습), done}`). 끝은 그 일이 이미 쓰는 기록으로 안다. 앱이 볼 수 없는 일(교재·다시 쓰기·준비물·원서접수 등)만 손으로 친다(`S.tk[id]=날짜`, `tk` 동작, 다시 누르면 되돌림).

## 쉬는 날·앞날 셈·시험 일정 살펴보기(v3.1.0)

"오늘 할 일을 못 하면 일정에 얼마나 차질이 나고, 다른 날을 어떻게 다시 짜고, 시험을 미룰지까지" 답하는 기능. 빚(다음 주로 넘어가는 몫)은 여전히 없고, 점수는 저절로 떨어지지 않으며, 빨강은 쓰지 않는다. `PLAN_V`는 2 그대로(새 기록이 없으면 계획 규칙이 바이트까지 같다).

- **쉬는 날·짧은 날**(`S.days[날짜] = {m}`, 0이면 쉬는 날, 60·120(주말 120·180)은 짧은 날, 평소 시간이면 지움): `budgetOf(t, kind, raw)`가 정한 시간을 쓰고(`raw`는 "평소대로 · n"용 평소 시간, 시험 날은 늘 0), `dayOff(t)`. 쉬는 날은 날짜 일(P0 핀: 원서접수·48시간 복기·준비물)만 남기고 나머지는 갈 곳과 함께 옮긴다(손글씨 바닥·단답 예외 없음), 자료를 기다리지 않고 바로 고정, 줄인 목표·`lvx`를 걸지 않는다(같은 날 "다시 공부할래요"로 흔적 없이 돌아감). 일요일이 쉬는 날이면 토요일이 손글씨 몫을 반이 아니라 들어가는 만큼 받고 주간 리포트도 토요일. 정하는 곳: 오늘 시간 창 "오늘은 쉬어요"(`cap-off`, 쉬기 전 시간을 함께 둠) → 쉬는 날 카드(파란 버튼 "다시 공부할래요" `off-clear`), 이번 주 날마다의 앞날 줄(`day-cap` → 그날 공부 시간 창 `day-set`, 오늘 단계는 그대로 `replan:'day'`), 설정 → 하루 공부 시간 아래 "쉬는 날·짧은 날"(기간 창 `days-sheet`·`days-set`, 한 번에 31일, 시험 날은 뺌, `days-del`). 지난주를 고정할 때 그 전 날짜는 지운다.
- **앞날 셈**(app.js "11-0b", 읽기만): `wkAhead(t, o)`가 이번 주 남은 필수를 오늘 몫과 같은 규칙으로 날마다 놓아 본다(그날 단계·줄인 목표, 주말 몫의 반 규칙, 밀린 세트는 평일 하나, 세트 복습은 처음 연 날부터, 토요일 모의는 교시마다, 날짜 일 분 `pinMin`). 결과 `{out:[{d, load, catch, lv}], spill, spillBack, cutFrom, lv3From}`, 기억 키 `'wa…'`(오늘 몫이 스스로 쓸 때 지움). `offDelta`·`placeTxt`·`outTxt`·`lvTxt`·`todayOnlyTxt`가 "오늘 쉬면 → 목 +31분 · 금 +8분 · 주말 +37분 / 이번 주 안에 다 따라잡아요 · 시험 일정은 그대로예요 / 말하기·자기 전은 오늘만이라 놓아줘요"를 만든다(분은 사용자가 연 창과 이번 주에만, 오늘 화면의 줄은 날짜만). 오늘 시간을 줄인 날은 "줄인 만큼 다른 날로: 목 +16분".

## 내비게이션(주소는 바꿔 쓰기만)

- 앱 안의 모든 이동은 `location.replace('#'+주소)`(같은 주소면 다시 그리기만)라 방문 기록(`history.length`)이 늘지 않는다. 그래서 지난 `#sess`·`#memo`로 되돌아가는 일이 없다. 기기 뒤로 가기 몸짓은 껐다(`App.js`의 `allowsBackForwardNavigationGestures={false}`).
- `route()`(hashchange): 열린 창을 닫고, 빈 흐름(SES 없는 `#sess`, MEMO 없는 `#memo`)은 그 위 화면이나 오늘로 바꿔 쓰고, `#set/날짜/탭`은 `#set/날짜`로, 그린 뒤 맨 위로. 위로(`goUp`) 온 화면은 떠날 때의 스크롤 자리로(`SCR[주소]`, `nav`·`goTab`이 떠날 때 적고 `UPH`가 한 번 고름: 기출 목록·세트 보관함·복습 탭 아래 줄로 돌아와도 그 자리), 펼친 숙제 카드가 있는 세트로 돌아오면 그 카드로(`.hw.focus`). 화면에 들어갈 때 한 번 하는 일은 `onEnter`(그리기는 기록을 쓰지 않는다).
- 앞으로: `nav(h,{from})`. 탭 주소는 `goTab`, 그 밖은 들어온 곳을 `RET[화면]`에 적고 바꿔 쓴다. 위로: `goUp()`(위쪽 "‹ 오늘"·"‹ 세트" 같은 이름 `UP_LABEL`, 기출 회차·단원 화면이 위면 "‹ 제140회"·"‹ 단원 이름"(6자가 넘으면 줄인 이름 "콘크리트Ⅱ" 등, 끝 화면 버튼도 "제140회로"·"기초로", `upLabel`·`closeLab`), 집중 모드는 "닫기", 왼쪽 가장자리 밀기). 위는 `upOf`: 세션·외우기는 연 곳(`SES.from`·`MEMO.from`, 외우기 안에서 연 외우기는 바깥 외우기), 기출 회차·단원은 그 목록, 그 밖은 `RET` → `PARENT` 표 → 오늘. 탭: `goTab`(그 탭 첫 화면으로 바꿔 쓰고 `RET`·`FLOW`를 비움, 지금 탭을 다시 누르면 맨 위로). 아래 탭 강조는 흐름을 시작한 탭(`tabOf`). `#study`·`#test`는 `TAB_ALIAS`로 연습 탭.
- 세션·가리며 외우기와 타이머가 도는 모의고사는 집중 모드(`body.focus`: 아래 탭 숨김, 위쪽 "닫기"). 뒤로·닫기·밀기는 하다 만 흐름을 지우지 않는다(오늘의 "이어서"). 끝 화면의 버튼(`sess-close`·`memo-close`)만 끝난 흐름을 지우고 위로 간다. 끝 화면의 "다음: …"(`endNexts`)은 정한 순서로 하나: 덜 한 세트 복습·카드 복습·오답이면 "이어서 · 남은 n문제" → 묶은 세트 복습의 다음 세트 → 오늘 몫 줄이 연 흐름(`FLOW = {id, from, at}`)이면 오늘 순서의 다음 줄 → 그 일의 다음(용어 퀴즈 다음 회차, "4지선다 10문 더" 등). 같은 `#sess`에서 잇는 것은 `chainSession`(연 곳은 그대로).
- 왼쪽 가장자리 밀기는 JS가 한다: 화면 왼쪽 20px 안에서 시작해(테이프 붙이기를 켠 동안(상자 밖 왼쪽 여백에서 시작해도)·테이프를 긋는 중·입력 칸·두 손가락·옆으로 밀리는 칸 위는 빼고) 0.7초 안에 오른쪽으로 70px 넘게, 위아래 60px 안이면 창이 열려 있으면 닫고(`dismissModal`), 아니면 `goUp()`(탭 첫 화면에서는 그대로). 카드·가리며 외우기·달력의 옆으로 밀기는 양쪽 가장자리 24px 안에서 시작한 것을 뺀다. 가리며 외우기 테이프의 `window` touchmove 리스너(`passive:false`)와 `.tsl`은 그대로다.
- 알림을 눌러 연 화면: `bridge.js`의 `_go(h)` → `window.__pe.go(h)` → `nav`(탭이면 `goTab`), 닫지 않은 "바뀐 점" 창은 그 위에 다시.
- 창 닫기: 사용자가 닫는 길(닫기 `sheet-close` · 바깥 `modal-close` · 가장자리 밀기)만 `dismissModal`(= `closeModal` + "바뀐 점"이면 본 것으로 + 그 창 아래서 모의 교시 시간이 끝났으면 다시 그려 시간 끝 창). `closeModal`은 그대로(여러 동작이 시작할 때 부른다). 교시 시간이 창 아래서 끝나면 아래 화면만 다시 그리고(집중 모드 끔) 알림, 점수 칸을 쓰는 중이면 다시 그리지 않고 집중 모드 표시만 끈다(`focusPaint`).
- 복원·초기화는 메모리의 흐름을 비운다(`flowReset`: 하던 세션·가리며 외우기·`FLOW`·`RET`·`SCR`·펼친 줄·나중에, 그 기록에 묶인 타이머, 모의의 고른 교시·연 키워드·목차 `SV['mkw:'·'mk:']`). 복원은 받은 세트를 이 휴대폰 것과 합치고(`setsMerge`: 같은 날짜는 `_rev`가 큰 것, 백업에만 있는 세트도 더함, 받아 오기 상태는 이 휴대폰 것) 곧바로 다시 받아 온다(초기화도). 지운 기록의 "이어서"가 남지 않는다. 백업(복사·파일)에는 그 백업의 날짜(`S.tk.backup`)를 넣고 만든다(`backupJSON`, 실패하면 전 날짜로).

  - 알려 둔 바뀜: 한 단원의 간격 온 카드만 복습하던 길(예전 암기 탭의 범위 "복습 대기")은 없앴다. "카드 복습"은 늘 전체 단원이고, 한 단원만은 연습 → 단원별 진도 → "이 단원 카드 외우기"(`study-unit` → `startStudy(단원)`, 그 단원의 간격 온 카드 + 새 카드, `S.range`는 그대로)나 범위를 고른 자유 연습·가리며 외우기로 한다.
- 연습 탭(`#practice`, `vPractice`, 예전 암기·테스트 탭을 합침. `#study`·`#test` 주소도 여기로): 범위 고르기 → 카드(카드 복습 n장 · 전체 단원, 새 카드, 자유 연습, 가리며 외우기 20장 · 별표·오답 먼저) → 문제(4지선다 10문, 용어 회상 10문, 수치 빈칸 10문, 빈칸 쓰기 10문, 논술 목차 떠올리기 5문, 단답 답안지 1문 · 10분) → 실전(이번 주·최근 모의고사, 기출 문제은행, 모의고사 만들기) → 단원별 진도(접힘). 끝 화면마다 "다음: …"(같은 것 한 번 더 또는 오늘 몫의 다음 줄, `endNexts`).
- 단답 답안지(`#dandap/카드id`, `vDandap`·`ddRows`·`ddSheet`): 카드 한 장을 1교시 단답 답안지(22줄 1면) 모양으로 옮겨 보여 준다. 새로 지어내지 않고 카드 내용만 쓴다: 문제("용어에 대하여 설명하시오.") → 답) → Ⅰ. 개요(정의 첫 문장, 괄호 속 영문은 원어) → Ⅱ. 주요 내용(키워드를 한 줄에 하나씩) → 그림 칸(4줄+제목, 직접 그리기) → Ⅲ. 결론(카드의 현장 문장, 없으면 직접 쓰기 안내) → 끝. 문장 끝은 `ddNoun`이 답안식 명사형으로(한다→함, 이다→임, 는다→음, ㅂ불규칙→움). 한 줄은 약 26자(`DD_W`, `ddWrap`), 글자 크기는 답안지 폭에 맞춰(`.ddwrap` 컨테이너, `100cqw/31.8`) 한 줄이 꺾이지 않게 한다. 22줄을 넘으면 2면으로 넘기고 알린다(카드 350장 기준 가운데값 20줄, 넘는 카드 약 7%). 정의의 나머지 문장은 "시간이 남으면 더할 내용", 10분 타이머(`one1`), 단답 첨삭 요청 복사(`copy-dd`, 프롬프트 p2에 용어). 세트 ① 용어·카드 창·연습 → 문제("단답 답안지 1문 · 10분", 범위에서 기출 카드 무작위 `ddRandom`, "다 썼어요"는 오늘 "단답 1문제 더" `x.dd2`)·숙제("단답 N문제", `PE_HW.dd`, `#dandap/카드id/날짜`의 "다 썼어요(숙제에 표시)")에서 들어간다.
- 용어 빈칸 쓰기(연습 → 문제 "빈칸 쓰기 10문", 세트 ① 용어 도구 줄, 세트 복습 창): 덱 전체 용어·키워드에서 만든 낱말 사전과 수치(`clozeTokens`)로 정의 속 빈칸을 무작위로 고른다(`fillCands`·`fillBlanks`). 하 1칸 첫소리 힌트, 중 2~3칸 글자 수 힌트, 상 4~6칸 힌트 없음. 입력은 `fillJudge`가 띄어쓰기·가운뎃점·대소문자를 무시하고 수치·단위는 정확히, 긴 낱말은 오타 1자까지 맞게 본다. 틀리면 오답 노트 `F:카드id`.
- 카드 넘겨 보기 세션(`vSess`의 card): 이전·다음 버튼과 카드를 옆으로 밀기(`sessPrev`·`sessAdvance`). 세트의 "카드 넘겨 보기"는 시작할 때 읽음으로 치지 않고 뒷면을 본 카드만 그 세트의 읽음(`sessMarkRead`, 항목의 `si`). 이전으로 돌아와 다시 고르면 처음 고르기 전 상태(카드 진도·오답)로 되돌리고 오늘 기록·점수에서 뺀 뒤 다시 매긴다(`sessSnap`·`sessUngrade`). 세트 넘겨 보기는 나갔다 다시 누르면 보던 카드부터(메모리의 세션 그대로, 앱을 껐다 켜면 `S.resume['flash:날짜']` 자리부터).
- 가리며 외우기(`#memo`, `vMemo`·`memoTick`): 카드 한 장을 줄(용어 `t`, 정의 문장 `d0…`, 키워드 `k0…`)로 나눠, 보이는 시간 → 가리는 시간을 정한 횟수(1·3·5·10) 또는 무한 반복. 가릴 것은 전체(용어만 남김), 탭해서 고른 줄(`S.memoPick[카드id]`, 카드마다 기억), 무작위 N줄(2~5줄, 가릴 때마다 용어를 뺀 줄에서 새로 고르고 바로 전에 가린 줄은 피함, `memoRoll`), 테이프(마스킹 테이프처럼 손가락으로 그은 곳만). 설정은 `S.settings.memo`(show·hide·mode all·pick·rand·tape·n·reps·auto). 다 돌면 다음 카드로 또는 멈춤. 마지막 카드에서는 "다음" 대신 "완료" → 끝 화면(`memoFinish`). 지운 카드는 "이 카드를 찾을 수 없어요"와 외우기의 "건너뛰기"(`memo-next`, 마지막이면 "완료"), 이어 하는 카드 목록에서는 지운 카드를 빼고 자리를 다시 센다(`startMemo`). 이어 하기: 나갔다 다시 누르면 보던 카드부터(`S.resume['memo:set:날짜']`, 연습 탭은 `memo:study`에 그날 카드 목록째로), 세트·연습 탭의 "이어 하지 않고 처음부터"(`resume-clear`)로 지운다. 세트 ① 용어(그 세트 카드, 보여 준 카드만 읽음)·연습 → 카드(범위에서 별표·오답·덜 익힌 순 20장)·복습 탭에서 들어간다. 집중 모드(아래 탭 숨김, 위쪽 "닫기"), 조절 줄(`.mctl`)은 아래에 붙는다. 도는 동안 화면 켜 두기, 다른 화면으로 가거나 앱을 내리면 멈춤. 틱마다 전체를 다시 그리지 않고 `paintMemo`가 가림 표시·남은 시간만 바꾼다. 남은 시간 막대(`.mbar`)는 눈에 덜 띄게 얇고 옅게. 위쪽 진행 막대는 지금 카드까지 친다(마지막 카드에서 꽉 참, 카드 넘겨 보기도 같음).
  - 테이프: "테이프 붙이기"를 켜면(`MEMO.edit`, 시간 멈춤, 상자에 점선, 카드 넘기기·낱말 꾹 누르기는 꺼짐) 아이폰 글자 고르기처럼 쓴다. 한 손가락으로 그냥 밀면 평소처럼 화면이 움직이고, 0.3초 꾹 누르면(`TP_HOLD`, 그 전에 10px 넘게 움직이면 스크롤로 보고 포기) 상자가 파란 실선이 되며 그대로 그은 범위가 테이프(여러 줄 이어서). 짧게 누르거나 꾹 눌렀다 그냥 떼면 그 낱말(조사·어미는 `glStem`으로 남김), 붙은 테이프를 누르면 뗀다. 마우스는 꾹 누를 것 없이 바로 긋는다. 두 손가락이 닿으면 아무것도 하지 않는다(긋던 것도 취소, 스크롤·확대는 기기에 맡김). 짧게 누른 것은 90ms 기다렸다 붙여(`tpTap`) 두 손가락으로 톡 친 것이 테이프가 되지 않게 하고, 미끄러지던 화면을 세우려고 누른 것(스크롤 150ms 안, `tpScrollT`)이나 누르는 동안 화면이 움직인 것은 붙이지 않는다. 긋는 동안에만 `window`의 touchmove를 막아 화면을 세운다. 이 리스너는 처음부터 `passive:false`로 달아 둬야 WebKit이 따른다(긋기 시작할 때 다는 리스너는 무시됨). 긋는 범위는 글자 요소를 바꾸지 않고 상자 위에 덮는 칸(`.tsl`, `memoSelPaint`가 `Range.getClientRects`로)으로 그린다: iOS는 손가락 밑 글자 요소가 바뀌면 그 뒤 터치 이벤트를 문서로 올려 보내지 않아 touchmove를 막지 못한다(예전 두 손가락 스크롤이 자주 끊기던 원인). 포인터 이벤트와 `caretRangeFromPoint`로 글자 자리를 찾는다(`memoTapeDown`·`memoTapeMove`·`memoTapeUp`, `memoOff`). 자리는 줄을 줄바꿈으로 이은 카드 글의 [시작, 끝)이고 글귀와 함께 `S.memoTape[카드id]`에 둔다(`memoTapeSet`이 겹친 것을 합치고, 카드 글이 바뀌면 `memoTapes`가 글귀를 다시 찾거나 버린다). 보일 때는 비치는 테이프, 가릴 때는 줄무늬 불투명 테이프. 테이프가 없는 카드는 전체를 가린다.
- 학습 달력(`#cal`, `vCal`): 오늘 화면 왼쪽 위 달력 아이콘(`calIconHTML`: 이달·오늘 날짜, 아래에 오늘 끝낸 종류 점), 더보기, 이번 주 → 기록에서 들어간다. 맨 위는 오늘 끝낸 공부(`calDayBody`: 접속 횟수·시각, 종류별 개수 칸, 종류별로 묶은 목록, 연속 학습 일수). 그 아래 한 달 칸마다 접속한 날은 숫자에 회색 원(오늘은 파란 원, 일요일 빨강·토요일 파랑 숫자, 시험·모의 날은 숫자 밑 빨간 줄), 끝낸 공부는 종류별 점(빨강 용어·파랑 논술·초록 퀴즈·테스트·주황 모의고사·보라 할 일). 날짜를 누르면 아래에서 올라오는 창으로 그날 내용(`cal-day`, 닫기는 `cal-close`). 달력을 옆으로 밀거나 ‹ › 로 이전·다음 달(`calShift`, 기록이 시작된 달부터 12달 뒤까지, 목표 시험이 더 뒤면 그 달까지, `calBounds`). 공휴일은 `KR_HOLI`(관공서 공휴일 규정, 대체공휴일 포함, 2026년부터 노동절·제헌절, 2026~2028년): 빨간 숫자와 짧은 이름(`holiShort`), 날짜 창에 이름. 임시공휴일이 정해지거나 2029년이 다가오면 표에 더한다. 기록은 `S.cal[날짜] = {in:[접속 시각], x:{키:[종류, 글]}}`(앱을 열거나 10분 넘게 내렸다 오면 `calOpen`, 세트 용어 읽음·퀴즈·논술 손글씨·과제·모의고사 다 씀·세트 다시 보기·넘겨 보기 끝·가리며 외우기는 `calMark`/`calUnmark`)에 더해 원래 기록(`S.daily` 카드 매김, `S.log` 테스트, `S.checks` 오늘 할 일, `sp.rev`)을 함께 읽어 예전 날짜도 보인다(`calItems`). 이번 주에 남은 일은 오늘 다음 날 ~ 일요일 칸에만 빈 동그라미(`calFwd`: 토요일 주간 모의고사 주황, 일요일 주간 마감 보라, 세트 복습이 돌아오는 날 회색, 색 설명 "앞으로(이번 주)", 날짜 창에 "앞으로(이번 주): …"). 공휴일·시험 일정 글은 `.cev`(예전 `.chev`는 화살표 아이콘과 이름이 겹쳐 그 규칙을 함께 받았다).

- 회원 승인(`native/member.js`, `native/Gate.js`, `firebase/firestore.rules`)
  - 휴대폰 구분은 IP가 아니라 Firebase 익명 계정. 그 refresh token을 expo-secure-store 키체인(`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`)에 둔다. 토큰이 무효(400)일 때만 새 계정을 만든다.
  - Firestore: `members/{uid}`(id·status·createdAt·code), `ids/{아이디}`(uid, 중복 방지), `codes/{코드}`(바로 승인), `admins/{uid}`(콘솔에서만 만든다), `msgs/{자동 ID}`(3.0.1, 관리자에게 보낸 문자: uid·id·text 500자·from join|wait|app·dev "iOS 18.1 · 앱 3.0.1"·at 서버 시각·read). members의 `hasOnly` 칸은 늘리지 않는다(예전 앱과 규칙이 같이 돌게 새 컬렉션으로). 문자는 아이디를 만든 뒤 따로 보낸다(규칙 게시 전이면 문자만 실패). 관리자는 모두 읽고 read만 바꾸며, 본인은 자기 것만 읽고 지운다(아이디 지우기 때 함께). 아이디 만들기는 members·ids를 commit 한 번으로 만들고, 규칙이 `getAfter`로 둘을 묶는다. commit 본문의 문서 이름은 인코딩하지 않는다(한글 아이디).
  - 승인 전에는 WebView 대신 `Gate` 화면만 띄운다. 승인된 상태는 키체인에 캐시해 인터넷 없이도 열고, 앱이 앞으로 올 때 다시 확인한다. 대기 중에는 15초마다 확인.
  - 웹 쪽: `PE_NATIVE.member`({id, admin, uid}) → 더보기에 아이디, 관리자면 "문자함"·"승인 관리"(`#admin`, `vAdmin`), 회원이면 "관리자에게 문자 보내기"(`#msg`, `vMsg`), 설정에 "아이디 지우기"(애플 5.1.1(v) 앱 안 계정 삭제). 요청은 `PE_IO.memberCall(op)` → `host.js`의 `member`(`MEMBER_OPS`: list·set·del·code-add·code-del·remove·unread·msg-read·msg-del·msg-send만).
  - 관리자 문자함(`#inbox`, `#inbox/uid`, `vInbox`): 탭 첫 화면(다섯 탭) 맨 위 오른쪽 `.ibxrow .ibx` 단추에 안 읽은 수(`.bdg`, 99+). 수는 `unread`(Firestore 세기 요청, 문서를 읽지 않음)로 탭 첫 화면을 그릴 때 1분에 한 번·앱으로 돌아올 때 센다(`IBX`, `ibxPoll`). 목록·문자는 `list`의 `msgs`(ADM과 함께, 규칙 게시 전이면 null → 안내). 사람을 열면(`onEnter`·목록을 받은 뒤) `ibxSeen`이 읽음으로. 승인 대기 줄에 마지막 문자, 문자 화면에서 바로 승인·거절.
  - `Gate`: 아이디 만들기에 "관리자에게 보낼 말"(초대 코드 없이 승인을 기다릴 때는 꼭 적는다), 승인 대기·거절 화면에서 더 보내기. `App.js`의 `DEV`가 iOS·앱 버전(기기 이름·위치는 넣지 않는다).
  - Firebase 값은 EAS 환경 변수 `EXPO_PUBLIC_FIREBASE_API_KEY`·`EXPO_PUBLIC_FIREBASE_PROJECT_ID`(production)로만 넣는다. 없으면 "설정이 빠진 빌드" 화면.
