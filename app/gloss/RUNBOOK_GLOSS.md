# 매일 용어 사전: 새 세트 낱말 풀이 더하기

예약 작업 "기술사 용어 사전"이 매일 아침(세트가 올라온 뒤) 이 순서대로 실행한다. 사용자에게 질문하지 않는다.

앱 "기술사 6개월"은 읽는 글의 낱말을 꾹 누르면 카드 → 내장 용어 사전(`app/web/data_gloss.js`) → 이 매일 사전(`app/gloss/daily.json`) 순서로 풀이를 찾는다. 이 작업은 새로 올라온 세트·모의고사에 나오는데 카드에도 사전에도 없는 낱말의 짧은 풀이를 `app/gloss/daily.json`에 더한다. 앱은 자료를 받아 올 때 이 파일도 받는다(앱을 다시 빌드할 필요 없음).

고치는 파일은 `app/gloss/daily.json` 하나뿐이다. `data/`, `pipeline/`, `app/web/`은 읽기만 한다.

## 0. 준비

저장소 폴더(클론한 절대 경로, 예: `/home/user/gisulsa-data`)에서:

```bash
git fetch origin main && git checkout main && git pull --ff-only origin main
cd app && npm ci
```

`npm ci`가 jsdom을 받는다(낱말 찾기를 앱과 똑같이 하려고 앱을 띄워 쓴다). 이후 명령은 모두 `app/`에서 친다.

## 1. 후보 뽑기

```bash
node scripts/gloss-daily.js candidates /tmp/gloss-cands.json
```

- `SKIP`이 나오면(처리할 새 세트·모의고사가 없음) 아무것도 바꾸지 말고(커밋·푸시 없음) 그 한 줄만 보고하고 끝낸다.
- 아니면 `/tmp/gloss-cands.json`에 `{"dates":[처리할 날짜], "cands":[{"key","forms","n","ex","dates"}]}`가 생긴다. `forms`는 그 낱말이 글에 나온 꼴(조사·어미를 하나씩 뗀 꼴 포함), `ex`는 예문, `n`은 나온 횟수.

## 2. 풀이 쓰기

`/tmp/gloss-cands.json`의 후보를 **모두** 훑어, 풀어 줄 가치가 있는 낱말만 골라 `/tmp/gloss-new.json`에 `[{"w": 표제어, "d": 풀이}]`로 쓴다. 고를 것이 없으면 빈 배열 `[]`.

**고르는 것**
- 토목·건설 기술 용어: 재료, 공법, 장비, 구조물과 부재, 시험과 시험값, 지반·구조·수리·포장·터널·댐·항만·교량 개념, 결함과 현상
- 건설 법령·계약·안전·공정·원가 용어
- 보통 어른이 모를 만한 한자어·전문어
- 대문자 영문 약어(풀 영문 이름과 우리말 뜻을 함께)

**빼는 것**
- 누구나 아는 일상어(관리, 확인, 원인, 높이, 서로, 모두, 정상 등)
- 동사·형용사 꼴, 부사, 조사, 낱말이 아닌 조각
- 이 토목 문맥에서 뜻을 확신하지 못하는 낱말. **추측해서 쓰지 말고 뺀다.**

**표제어(`w`)**: 그 후보의 `forms` 중 사전에 올릴 바탕꼴(조사·어미가 없는 낱말)을 고른다. 예: `forms`가 `["누수와","누수"]`면 `누수`. 바탕꼴이 `forms`에 없으면(조사 떼기로 낱말이 잘린 꼴만 있으면, 예: `정착길`) `forms` 중 실제 낱말인 가장 긴 꼴을 쓰고, 그것도 없으면 뺀다. `w`는 반드시 `forms` 안의 꼴이어야 한다(아니면 3단계 검사에서 빠진다).

**쓰는 규칙(`d`)**
- 한국어 1~2문장, 모두 25~90자(검사는 10~140자).
- 표제어로 시작하지 않는다. 뜻을 바로 쓴다. 예: 동바리 → `콘크리트를 칠 때 거푸집과 그 위 하중을 아래에서 받쳐 주는 임시 기둥과 받침재.`
- 예문(`ex`)을 보고 토목 시공의 뜻으로 쓴다(같은 글자라도 문맥에 맞는 뜻).
- 수치·기준값은 표준이고 확실할 때만 쓴다. 아니면 성질로 설명한다.
- 마크다운·따옴표·줄바꿈·꺾쇠(`<` `>`)·이모지를 쓰지 않는다.
- 약어는 풀 영문 이름으로 시작한다. 예: RQD → `Rock Quality Designation, 암질지수. 시추 코어 중 길이 10cm 이상 조각의 합을 전체 길이로 나눈 비율로 암반 상태를 나타낸다.`

## 3. 검사하고 더하기

```bash
node scripts/gloss-daily.js check /tmp/gloss-new.json
```

`뺌(...)`으로 나온 것 중 고칠 수 있는 것(길이·형식, 표제어로 시작, 표제어가 `forms` 밖)은 `/tmp/gloss-new.json`에서 고치고 다시 `check`한다. 카드가 있거나 이미 사전에 있는 것은 그냥 둔다(빠져도 된다). 그다음:

```bash
node scripts/gloss-daily.js add /tmp/gloss-new.json
npm test
```

`add`는 통과한 풀이를 더하고, 처리한 날짜를 `done`에 적는다(더한 것이 0개여도 날짜는 적힌다. 다음 날 같은 세트를 다시 보지 않게). `add` 뒤에는 같은 날짜로 다시 더할 수 없으니 고치기는 `check` 단계에서 끝낸다. `npm test`가 "모두 통과" 세 번이 아니면 올리지 않고 그 사실을 보고한다.

## 4. 올리기

```bash
cd ..
git add app/gloss/daily.json
git commit -m "용어 사전: <처리한 날짜> 새 낱말 <N>개"
git fetch origin main && git rebase origin/main && git push origin HEAD:main
```

푸시가 네트워크 오류로 실패하면 2·4·8·16초 쉬고 최대 4번 다시 한다. 다른 예약 작업과 겹쳐 rebase가 충돌하면 `git rebase --abort` 후 `git reset --hard origin/main`으로 맞추고 0단계부터 다시 한다.
