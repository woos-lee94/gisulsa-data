# 평일 아침 세트 만들기

목표: 오늘 날짜의 세트 JSON 하나를 `data/sets/`에 올린다. 사용자는 앱을 열기만 하면 자동으로 받는다. Claude 앱에서 따로 풀 것은 없다.

## 순서

1. 브리프 보기
   ```
   python3 pipeline/tool.py today
   ```
   첫 줄이 `SKIP`이면 아무것도 만들지 말고 그 이유를 한 줄로 보고하고 끝낸다.

2. 재료 고르기(브리프 후보에서)
   - 새 용어: 규칙 개수만큼 `[새 용어 후보]` 위에서부터. `※` 메모가 있는 항목은 메모를 따른다. 후보가 모자라면 브리프 안내대로 직접 고른다.
   - 기존 카드: 나머지 개수를 `[기존 카드 후보]`에서 ref로. 오늘 새 용어와 이어지는 것을 고른다.
   - 논술: `[논술 후보]`에서 1문제. 오늘 단원과 맞는 것.
   - `[최근 세트]`와 주제가 겹치지 않게 한다.

3. 사실 확인
   새 용어 정의와 논술 목차에 넣을 수치·기준·법령 조항은 WebSearch/WebFetch로 1차 출처(국가건설기준센터 KDS·KCS, 국가법령정보센터 현행 법령·행정규칙, 국토교통부·환경부 고시)를 찾아 확인한다. 확인하지 못한 수치는 쓰지 않고 `check`에 적는다. 확인한 출처는 카드의 `basis`에 짧게 적는다.

4. 파일 쓰기: `data/sets/<날짜>.json`
   형식과 문체는 `pipeline/spec_set.md`를 따른다. 기존 카드 정의는 `pipeline/deck.json`에서 볼 수 있다.

4-1. 따로 대조하기
   새 용어 카드(`ref`가 아닌 카드)와 논술 목차에 들어간 수치·기준값·조항만 뽑아 목록으로 만들고, 하위 에이전트 한 명에게 1차 출처와 대조하게 한다. 그 에이전트에게는 세트 파일 전체가 아니라 그 목록만 주고, 항목마다 `맞음 / 틀림(바른 값과 출처) / 찾지 못함`으로 답하게 한다.
   틀림은 고치고, 찾지 못함은 정의에서 빼고 `check`로 옮긴다.

5. 검사
   ```
   python3 pipeline/tool.py check-set <날짜>
   ```
   오류가 0개가 될 때까지 고친다. 경고는 읽고 판단한다(고칠 이유가 없으면 그대로 둔다).

6. 올리기
   ```
   python3 pipeline/tool.py publish-set <날짜>
   git add -A
   git commit -m "세트 <날짜>: <제목>"
   git push
   ```
   push가 거부되면 `git pull --rebase` 후 다시 push한다.

7. 확인
   ```
   curl -s "https://raw.githubusercontent.com/woos-lee94/gisulsa-data/main/data/index.json?t=$(date +%s)" | head -c 400
   ```
   오늘 날짜가 `sets`에 보이면 끝. 반영까지 몇 분 걸릴 수 있다.

## 마지막 보고(사용자 휴대폰 알림으로 간다)

세 줄 이내, 아래 틀로 쓴다. 링크나 파일 경로는 넣지 않는다.

```
오늘 세트가 올라갔어요: <제목>
새 용어 <N>개(<용어1>, <용어2>…), 논술 1문제(<기출 회차>)
앱을 열면 자동으로 받아요.
```

실패했으면 무엇이 안 됐는지 한 줄로 쓴다(예: `세트를 만들지 못했어요: git push 권한 오류`).
